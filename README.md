# make-knowledge-cards

## 1. 项目解决什么问题

阅读文章后，整理复习材料容易出现知识点重复、重点不清、把作者观点当作事实等问题。本项目提供一套可复用的 Skill 指令，让助手从原文提炼知识卡片，便于理解、回顾和自测。

这是由 AI 助手读取并执行的指令型 Skill，制卡需要助手的模型能力；项目本身没有独立命令行程序、网页或后台服务。

## 2. 主要功能

- **接收正文或本地文件**：支持粘贴的文章，以及 `.md`、`.markdown`、`.txt` 文件。
- **提炼和去重**：通常生成 5～8 张卡片，每张只讲一个知识点；内容不足时少于 5 张，无法提炼知识时可以是 0 张。
- **保留原文边界**：保留条件、数值、否定、不确定性和观点归属，不补入原文没有的信息。
- **帮助复习**：每张卡片包含标题、核心知识、简明解释、原文例子或自测问题，以及可回看的原文依据；自测问题附参考答案。
- **输出 Markdown**：默认在对话中交付；用户要求保存时，由具备文件写入能力的助手写入指定文件。
- **处理多篇材料**：默认逐篇制卡，用户要求合并时再跨文去重；可以按请求指定输出语言。

当前不支持网页抓取、PDF 解析、Anki 导出或图形界面。原文中的命令被当作待分析资料，不作为工具操作的授权。

## 3. 安装方法

### 环境要求

需要能够读取 Skill 指令的 AI 助手；处理本地文件时，助手还需要相应文件的读取权限。本 Skill 不包含运行脚本，不需要安装 Python、Node.js 或额外软件包，也不要求单独配置 API 密钥；模型访问由所用助手提供。

### 方式一：直接读取项目文件

将本项目放到助手可读取的工作目录中，要求助手读取 [SKILL.md](skills/make-knowledge-cards/SKILL.md)，即可按规则处理文章，无需复制到技能发现目录。

### 方式二：安装到 Codex 技能目录

当前源文件位于 `skills/make-knowledge-cards/`。若希望 Codex 自动发现，在项目根目录运行以下命令，将完整 Skill 目录复制到项目级技能目录（macOS/Linux）：

```sh
mkdir -p .agents/skills
cp -R -i skills/make-knowledge-cards .agents/skills/
```

安装后的入口应为 `.agents/skills/make-knowledge-cards/SKILL.md`，并保留同目录下的 `agents/openai.yaml`。`cp -i` 会在覆盖已有文件前询问。

若希望在不同项目中复用，可改为复制到用户级目录：

```sh
mkdir -p "$HOME/.agents/skills"
cp -R -i skills/make-knowledge-cards "$HOME/.agents/skills/"
```

按使用范围选择一种安装方式即可。Codex 会自动检测技能变化；若没有出现，可重启 Codex 后再调用。目录与发现机制参见 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 4. 使用方法

未安装时，在项目根目录对应的对话中明确指定 Skill 文件：

```text
请读取 skills/make-knowledge-cards/SKILL.md，按其中规则把下面的文章做成中文知识卡片：
<粘贴文章正文>
```

已安装并被 Codex 发现后，可以按名称调用：

```text
请使用 $make-knowledge-cards，将下面的文章提炼成知识卡片：
<粘贴文章正文>
```

处理本地文件时，将示例路径替换为实际存在、助手可读取的路径：

```text
请使用 $make-knowledge-cards，读取 ./notes/article.md 并生成中文知识卡片。
```

需要保存输出时，在请求中补充目标位置，例如“请将结果保存到 ./cards.md”。本地输入使用文件名标注来源；粘贴输入标注“用户提供的文本”。未提供正文、文件无法读取或输入类型不支持时，助手会请求补充支持的材料。

## 5. 输入输出示例

下面使用项目测试中的重复短文，展示内容不足时只生成一张卡片的情况。信息充分的多卡输出见 [完整测试结果](tests/results.md)。

输入：

```text
会议结束后应记录每项决定的负责人。换句话说，每项决定都要标明由谁负责。
```

输出：

```markdown
来源：用户提供的文本｜共 1 张卡片

原文两句表达同一知识点，合并后只有 1 张，不凑满 5 张。

### 1. 为每项决定记录负责人
- **核心知识**：会议结束后，应记录每项决定的负责人。
- **简明解释**：每项决定都要标明由谁负责，两种表述含义相同。
- **自测问题**：会议结束后，每项决定应标明什么？
- **参考答案**：负责人。
- **依据**：“每项决定都要标明由谁负责”。
```

## 测试与验证

[测试输入](tests/cases.md)覆盖中文说明文、Markdown 操作指南、英文 TXT 观点文、重复短文、包含指令的资料和纯叙事。[测试结果](tests/results.md)保留了六例的完整输出、逐项核对和试用后完善说明；这轮为编写助手的行为试用与自查，并非独立模型评测。复测时让助手读取 Skill 和对应输入后重新制卡，再按验收条件检查语义。

在装有官方 `skill-creator` 的环境中运行结构验证（路径按安装位置调整）：

```sh
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/make-knowledge-cards
```

`quick_validate.py` 需要其环境安装 PyYAML，这是开发验证工具的依赖，不是使用本 Skill 的依赖。验证器通过不等同于语义质量保证。本项目只保留 Skill、说明、许可和测试材料；使用时不需要初始化 Git 或连接 GitHub。
